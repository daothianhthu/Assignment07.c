# 과제 07 - 인접 행렬과 인접 리스트의 성능 비교

## 1. 과제 개요

정점이 100개(번호 0~99)인 **무방향 단순 그래프**를 인접 행렬(Adjacency Matrix)과 인접 리스트(Adjacency List)로 각각 표현하고, 두 표현 방식의 메모리 사용량과 그래프 연산의 비교 횟수를 측정합니다.

- 희소 그래프(Sparse Graph): 정점 100개, 간선 100개
- 밀집 그래프(Dense Graph): 정점 100개, 간선 4,000개
- 자기 자신을 연결하는 간선(Self-loop)과 중복 간선은 생성하지 않습니다.
- 같은 그래프 간선 집합을 행렬과 리스트에 모두 저장하여 비교합니다.

정점 100개인 무방향 단순 그래프가 가질 수 있는 최대 간선 수는 `100 × 99 / 2 = 4,950`개입니다.

## 2. 파일 구성

| 파일        | 역할                                                                        |
| ----------- | --------------------------------------------------------------------------- |
| `main.c`    | 프로그램 실행, 두 그래프 실험 제어, 연산 비교 횟수 및 메모리 사용량 출력    |
| `graph.c`   | 중복되지 않는 무작위 간선 생성                                              |
| `matrix.c`  | 인접 행렬 초기화, 간선 추가·삭제·연결 확인, 인접 정점 출력                  |
| `list.c`    | 인접 리스트 초기화, 간선 추가·삭제·연결 확인, 인접 정점 출력 및 메모리 해제 |
| `measure.c` | 실험 결과 출력                                                              |
| `README.md` | 과제 설명, 실행 방법 및 측정 기준                                           |

## 3. 컴파일 및 실행

모든 `.c` 파일이 같은 디렉터리에 있는지 확인한 다음 터미널에서 실행합니다.

```bash
gcc -Wall -Wextra -std=c11 main.c graph.c matrix.c list.c measure.c -o main
./main
```

`./main`을 실행할 때마다 난수 시드가 현재 시간으로 설정되므로 생성되는 그래프와 비교 횟수는 실행마다 달라질 수 있습니다. 현재 `main.c`는 명령행 인자로 시드를 받지 않으므로 `./main 7`로 실행해도 시드 7이 적용되지는 않습니다.

## 4. 구현 방식

### 4.1 인접 행렬

`int matrix[100][100]` 배열을 사용합니다. 정점 `u`와 `v` 사이에 간선이 있으면 `matrix[u][v]`와 `matrix[v][u]`를 모두 1로 설정합니다. 간선이 없으면 값은 0입니다.

### 4.2 인접 리스트

각 정점에 연결 리스트를 하나씩 둡니다. 간선 `(u, v)`를 저장할 때 `u`의 리스트에는 `v`를, `v`의 리스트에는 `u`를 저장합니다. 새 노드는 각 리스트의 맨 앞에 추가합니다.

## 5. 측정 방법

프로그램은 각 그래프에 대해 다음 작업을 수행합니다.

1. 같은 간선 집합을 인접 행렬과 인접 리스트에 저장합니다.
2. 생성된 첫 번째 간선이 존재하는지 두 표현 방식에서 확인합니다.
3. 정점 0의 인접 정점을 출력합니다.
4. 간선 삭제 전에 자료구조의 메모리 사용량을 계산합니다.
5. 처음 선택한 간선 하나를 행렬과 리스트에서 삭제합니다.
6. 각 연산의 비교 횟수를 출력하고 리스트 메모리를 해제합니다.

### 5.1 메모리 사용량

- **인접 행렬:** `sizeof(matrix)`로 배열의 크기를 계산합니다. 일반적인 4바이트 `int` 환경에서는 `100 × 100 × 4 = 40,000 Bytes`입니다.
- **인접 리스트:** 현재 코드는 헤드 포인터 배열의 크기와 노드 수를 바탕으로 `sizeof(adj) + 2 × edgeCount × sizeof(Node)`를 계산합니다. 일반적인 64비트 환경에서 포인터는 8바이트, `Node`는 패딩을 포함해 보통 16바이트이므로 희소 그래프는 약 4,000 Bytes, 밀집 그래프는 약 128,800 Bytes로 계산됩니다.
- 이 계산은 리스트 노드의 구조체 크기를 기준으로 하며, `malloc`의 내부 관리 공간은 포함하지 않습니다.

### 5.2 비교 횟수 기준

비교 횟수는 각 함수에 구현된 카운터 증가 위치를 기준으로 계산합니다.

| 연산           | 인접 행렬                               | 인접 리스트                                            |
| -------------- | --------------------------------------- | ------------------------------------------------------ |
| 간선 추가      | 대상 행렬 칸을 확인할 때 1회            | 중복 간선 확인을 위해 방문한 리스트 노드 수            |
| 간선 삭제      | 대상 행렬 칸을 확인할 때 1회            | 양쪽 리스트에서 대상 노드를 찾으며 방문한 노드 수의 합 |
| 연결 여부 확인 | 대상 행렬 칸을 확인할 때 1회            | 대상 정점을 찾을 때까지 방문한 노드 수                 |
| 인접 정점 출력 | 해당 정점의 행 100칸을 확인하므로 100회 | 해당 정점의 리스트 노드 수                             |

현재 프로그램에서 간선 추가 비교 횟수는 **초기 그래프를 구성하는 모든 간선 추가 과정의 합계**입니다. 간선 삭제는 한 번만 수행하며, 연결 여부 확인도 한 번만 수행합니다. 따라서 아래 출력값을 다른 실험 설계(예: 추가·삭제 10회)의 결과와 직접 비교해서는 안 됩니다.

## 6. 결과 해석 시 참고 사항

실행 결과는 난수로 생성된 그래프에 따라 달라집니다. 결과를 보고할 때는 실제 실행 화면에 출력된 수치를 사용해야 하며, 예시 수치를 고정된 결과처럼 기재하지 않습니다.

일반적으로 인접 행렬은 간선 존재 여부를 확인하거나 간선을 추가·삭제할 때 일정한 횟수의 배열 접근으로 처리할 수 있습니다. 반면 인접 리스트는 대상 정점을 찾기 위해 리스트를 순회해야 하므로 비교 횟수가 정점의 차수와 노드 순서에 따라 달라집니다. 희소 그래프에서는 인접 리스트가 메모리를 적게 사용할 가능성이 크며, 밀집 그래프에서는 리스트 노드가 많아져 메모리 사용량이 커질 수 있습니다.

## 7. 결론

인접 행렬과 인접 리스트 중 어느 표현이 더 적절한지는 그래프의 밀도와 필요한 연산에 따라 달라집니다. 인접 행렬은 간선 존재 여부 확인과 간선 변경이 간단하고 일정한 비용으로 수행되지만, 정점 수에 비례해 모든 칸을 저장합니다. 인접 리스트는 실제 간선에 해당하는 노드만 저장하므로 희소 그래프에서 메모리와 인접 정점 순회에 유리할 수 있지만, 간선 존재 여부 확인·추가·삭제에는 리스트 탐색 비용이 발생합니다.

이 프로그램은 희소 그래프와 밀집 그래프를 각각 생성해 두 표현 방식의 메모리 사용량과 연산별 비교 횟수를 관찰합니다. 최종 보고서에는 본인이 실제 실행한 출력값을 근거로 결과를 분석합니다.
